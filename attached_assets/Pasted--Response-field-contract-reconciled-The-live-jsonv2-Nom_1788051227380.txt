## Response-field contract reconciled

The live `jsonv2` Nominatim search endpoint returns:

- `category` — current replacement for the former `class` field
- `addresstype`
- `type`
- `name`
- `namedetails`
- `osm_type`
- `osm_id`
- `lat`
- `lon`
- `importance`
- `place_rank`
- `display_name`
- `boundingbox`
- `place_id`
- `licence`
- `address` when `addressdetails=1` is requested

The sieve now uses them as follows:

| Field | Use |
|---|---|
| `category` | Primary classification gate; reported as “class” for the review table |
| `addresstype` | Second classification gate against administrative units, settlements, roads and postcodes |
| `type` | Corroborates generic words such as `slap ↔ waterfall` |
| `name`, `namedetails` | Diacritic-insensitive name matching and language variants |
| `address` | Structured village/town/municipality/county corroboration for extra place tokens |
| `osm_type`, `osm_id` | Stable OSM identity and reporting |
| `lat`, `lon` | Straight-line distance and hard-ceiling enforcement |
| `importance` | Ranking and equal-plausibility detection |
| `display_name` | Display only; never used as matching evidence |

Missing `category` or `addresstype` now fails closed as `missing-classification`. The sieve no longer reads the absent legacy `class` field.
