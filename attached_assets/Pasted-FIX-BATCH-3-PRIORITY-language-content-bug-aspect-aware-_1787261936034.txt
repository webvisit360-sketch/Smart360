IMG-1 — Aspect-aware hero rendering (new BINDING rule, extension C4)

Problem: Skuter, Čoln and Parkirišče photos are LANDSCAPE images inside a tall
portrait hero. object-fit: cover therefore crops them to a narrow vertical
slice — the owner sees only a detail of the scooter/boat, and only sky on
Parking. No focal point can ever fit a whole landscape subject into a tall
cover crop, so this is a shell rule, not a data task.

New rule (extends the prototype; the prototype's placeholder photos do not
exercise this case — this text is binding, precedent C1):





Compute mismatch = imageAspect / containerAspect (aspect = width/height).



If mismatch <= 1.6 and >= 1/1.6: keep today's behavior — cover +
focal-point object-position.



Otherwise render the "blur-fill" hero:





background layer: the SAME image, object-fit: cover, scaled ~1.08,
filter: blur(24px) brightness(.92) saturate(1.05), clipped to the hero;



foreground layer: the image with object-fit: contain, centered, so the
WHOLE photograph is visible;



back button, gallery dots and sheet overlap unchanged.



Applies to detail heroes and gallery slides. Grid/list thumbnails keep
cover (small crops are fine there).



Recompute on resize/orientation change.
