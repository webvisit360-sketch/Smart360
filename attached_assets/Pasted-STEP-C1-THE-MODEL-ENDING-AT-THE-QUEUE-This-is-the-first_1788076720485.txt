2 · THE MODEL CALL
GPT-5.6 Terra through Replit AI Integrations, structured output, in batches of
fifteen to twenty places, each batch retried once on schema failure. Not one
request for sixty.

The server builds the prompt. The browser never supplies or influences the
rules. Inputs: origin coordinates and machine-resolved region, tenant type,
the three ranges above, the existing category catalogue, the house style, the
durable rejection list, and the standing rule that we never write descriptions
for hospitality, shops, pharmacies, filling stations or health services.

Per place the model returns: proposed name, an existing category id, a
Slovene description, translations into EN, DE and IT, a geocoding lookup hint,
and a one-line reason it belongs. Existing categories only in C1 — if nothing
fits, the model says so in the reason and the place still comes through.

THE SCHEMA MUST MAKE LYING IMPOSSIBLE, NOT MERELY FORBIDDEN. There must be no
property anywhere in the output for coordinates, distance, travel time,
opening hours, prices, telephone numbers or street addresses. Not optional
fields, not ignored fields — absent. The model cannot supply what the schema
has no room for.

4 · THE RUN REPORT — the tool produces it, not a person
Every run ends by writing its own report, readable in the admin:
· proposed, confirmed, could not be confirmed, and the refusal rule for each;
· how many fell outside each range;
· duplicates merged;
· input and output tokens, and the cost in dollars;
· wall-clock time, and how much of it was the Nominatim throttle.
Without the tool producing this itself, the first real test gets judged by
feel, and by feel it will always look good.
