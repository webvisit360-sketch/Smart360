A — LIVING GUIDE IDENTITY AND CONTACT PARITY
═══════════════════════════════════════════════

Living Guide renders neither logoUrl nor logoSquareUrl and omits Viber, and
Instagram is stored and labelled but rendered by neither guest system. Three
pieces of information the host has already entered never reach a guest. Close
all three as one change.

Reference: lg-identiteta.html, attached — three phone mockups showing exactly
this.

1 · Logo on the cover
Above the cover title, left-aligned in the same column as the kicker and the
property name, 52 px square, on a soft light plate so it reads on any
photograph. Rendered only when a logo is uploaded.

2 · Square mark on Home
logoSquareUrl, falling back to logoUrl, 34 px, in the Living Guide Home header
beside the property name.

3 · Viber and Instagram in the contact rows
Order: Pokliči, WhatsApp, Viber, Instagram, E-pošta. A row renders only when
its field has a value. Normalise Instagram from @name, plain username or a full
profile URL into a safe https link — never render an arbitrary raw URL.
Translations and accessible names in every enabled language, not Slovenian only.

4 · No placement controls, now or later
One position, one size, decided here. Do not add sliders for logo size,
opacity, horizontal or vertical placement in Living Guide. If a particular logo
sits badly there, that is one design problem for us to solve once — not a knob
for every host to adjust.

B — THE APP DECIDES THE TOUR PLAYER'S CHROME
═══════════════════════════════════════════════

Correction to an earlier premise: hosts never paste the tour URL. The owner
shoots the drone panoramas and configures Kuula himself, for every tenant. The
reason for this change is therefore not host error — it is that he should not
retype six display parameters from memory for the fifteenth tenant.

When embedding a Kuula tour, force the display parameters at render time
regardless of what is stored: thumbnails off, info off, fullscreen off, vr off,
gyro off, provider logo hidden, gentle autorotate preserved. Pass through any
parameter that identifies which tour or collection to show. Leave the stored
value untouched — normalise for display only, so tours already stored are
covered and nothing typed is destroyed.

The thumbnail strip in particular is not merely noise: the owner navigates
between panoramas with hotspot icons placed on the panoramas themselves, so the
strip is a second and worse navigation.

Report which parameters you force and which you pass through before building.
If one is ambiguous, say so rather than guessing.

═══════════════════════════════════════════════
