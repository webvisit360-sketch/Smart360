TWO FIXES, IN THIS ORDER

1 · THE MANUAL CONFIRMATION PATH — specified in Step B, never built
An unconfirmed proposal reaches the operator, who can place it on a map by
hand. Name, model description, refusal rule, and a map to drop the pin on.
A hand-placed coordinate is marked as operator-sourced, never machine-verified,
and carries that provenance forward exactly like the shortened-query badge.
Volume is about thirty per run, mostly nearby, so this is the difference
between a guide about the region and a guide about the valley.

2 · FOR THE NEAR RING, ENUMERATE INSTEAD OF SEARCHING
Do not search the world for a small local church. Query OSM for everything
within the near range of the origin — a bounded set of a few hundred features
with names — and match the model's proposals against THAT set.

Inside a geographically bounded candidate set, tolerant name matching is safe,
because there is only one church in Rečica. Against a global search it is not,
which is why the current sieve must be strict and why strictness costs us the
neighbourhood. Excursions keep the current strict global sieve; the near ring
gets the enumerated one.

Report how you would implement this — Overpass or Nominatim bounded search,
what the candidate set contains, and how a match is decided — before building
it.
