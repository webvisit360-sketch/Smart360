Enostaven is a presentation layer over the same published guide, not a separate
content tree. Generate tiles from actual published categories and runtime
features; never copy the reference tenant's category list into production.
Trend must remain unchanged outside explicitly requested landing and home-header changes.
Identification belongs at the first order/rental, never at Enostaven entry.

**Why:** The owner specified these boundaries and supplied two binding HTML
references for Drobež and Meli Pu. Real published structures may differ from
those illustrative sheets.

**How to apply:** Compare both reference-shaped fixtures and actual published
snapshots. Measure the rendered result, not just CSS. Explicit written
requirements take precedence where the reference itself differs: square tiles,
19% radius and white pictograms. Do not claim
pixel identity for the full reference image when these differences exist.

Landing corrections apply to BOTH Trend and Enostaven: bottom-edge open button
(16px extra clearance above the device safe area), host block immediately above, untinted photo/walk,
only subtle host-text shadows. Seven identical 44px circular center-cropped flags
have the pale tile-style border and thin gap; SL last, no JEZIK label, no selected
size change. These replace the earlier rectangular/larger-selected flag reference.

**Why:** The owner explicitly corrected the landing layout and flag treatment.
**How to apply:** Keep these changes landing-only. Evidence must distinguish
photo-mode browser fixtures from a verified interactive external virtual walk.

The home return circle on Enostaven and Trend keeps its flag-matching dimensions,
border and palette, but uses a strong white solid back arrow rather than “360”.
It appears only with configured landing media and returns to that landing.
A separate matching arrow on the virtual walk reloads ONLY the iframe at its
configured starting URL; never reload the entire guide. The owner explicitly
requested this landing reset control after real-user feedback, superseding the
earlier prohibition on landing arrows.

**Why:** The owner specified the placement and conditional visibility.
**How to apply:** Distinguish home navigation from landing iframe reset. Cross-origin
panorama detection is not available without provider cooperation; do not add
untrusted scripts or claim an aerial start unless verified in the actual tour.
Physical iPhone/PWA claims require device evidence, not only viewport simulation.

The owner's later SVG catalogue supersedes the earlier HTML pictograms for
Apartmaji (bed), Vhodna vrata (open door), and Domači izdelki (jar). Match the
button label; generic Nastanitve keep the building.
**Why:** These three replacements were explicitly supplied to distinguish tiles.

The owner's expanded category-icon catalogue is now the binding pictogram source
for the whole Enostaven library, including its seven-language keyword lines.
Preserve exact SVGs rather than drawing a substitute from the English description:
the supplied Breakfast SVG is coffee only, although the message mentions a croissant.
Existing seed icon values must not prevent automatic category-label matching;
explicit catalogue choices are the user-controlled override, with an automatic reset.
**Why:** The owner asked for cross-tenant matching and host/operator overrides, not
a one-off replacement of selected tenants' data.
**How to apply:** Keep catalogue-source fidelity, reserve generic pin/cart for
unmatched labels, and distinguish fixture screenshots from live-production evidence.

Dynamic Enostaven is a home-background mode, not a replacement tile palette:
retain the tenant's Bordo/Modra/RGB choice. Its backgrounds and solar boundaries
must have one shared source with weather; mock gradient literals must never become
an independent implementation. Missing valid solar/weather data keeps the static
palette rather than inventing a time-of-day.
**Why:** The owner explicitly requires weather/home parity and unchanged tiles.
**How to apply:** Compare the shared gradients to the binding dynamic mock and
flag differences; use dark brown evening text and preserve landing isolation.

Enostaven runtime pages use time-independent light neutral chrome, white reading
cards (including under photos), and accents derived from the tenant palette.
Program must not inherit its original always-navy design in Enostaven. Day-part
color remains confined to dynamic home and weather skins; tiles, back circles,
and landing actions retain their palette. Trend's existing appearance is excluded.
**Why:** The owner reported navy Program at 09:42 and requested a consistent
Enostaven experience while explicitly prohibiting changes to Trend.
**How to apply:** Scope overrides to Enostaven, test morning/night and all palettes,
and do not claim Trend's existing night reading sheets are white.
