# Email lockup audit

Scope: existing email wordmarks only. `Smart360` in ordinary message copy, headings, subjects, footers and sender addresses is **not** a brand-wordmark element. The public image URL follows the existing `https://smart360.info/brand/…` pattern; this audit does not imply publication or email delivery.

Before the update, the shared `renderEmail` kicker in `emailTemplate.ts` displayed the official 20 × 20 mark (`smart360-znak-40.png`) followed by HTML brand text. Its text had `font-size:13px`, `font-weight:800`, `letter-spacing:.14em`, `text-transform:uppercase`, and `color:#121A14`; the welcome theme specified `Archivo,-apple-system,BlinkMacSystemFont,'Segoe UI',Roboto,Arial,sans-serif`, while the other theme used `-apple-system,'Segoe UI',Roboto,Arial,sans-serif`. The ready-notice override displayed the mark at 46 × 46 and HTML `SMART360` text in `Archivo,-apple-system,BlinkMacSystemFont,'Segoe UI',Roboto,Arial,sans-serif`, `font-size:13px`, `font-weight:800`, `letter-spacing:.14em`, and **green `#157347`** (no explicit `text-transform` on that uppercase literal). No HTML body copy or tenant name needs to be converted to an image.

After the latest owner correction, *every existing brand-mark image* in these templates uses **one** opaque white RGB lockup: `artifacts/smart360/public/brand/smart360-email-lockup-host-594x138.png` (594 × 138 pixels). The official unchanged SVG mark and actual loaded `Archivo-800.ttf` render the embedded uppercase wordmark at **24px**, `#121A14`, with `.02em` spacing and **12px** mark-to-text gap, with no HTML wordmark. The real Archivo-800 canvas measurement (letter advances plus tracking) is **139.128px**; thus `ceil(46 + 12 + 139.128) = 198px` overall width and 46px height. All shared and ready headers now display **198 × 46**, with both HTML dimensions and matching inline CSS; the single raster has 3× resolution. The SVG and actual font are drawn together on white at 4× the final resolution and the composite is Lanczos3-downsampled. Earlier public email assets, including the previous 558 × 138 lockup and 60/138px mark files, are preserved for previously received emails.

**Host-form source discrepancy:** On inspection, the current web `BrandLockup` component defaults to `markSize=52`, `textSize=26` and `gap:8`; the login page renders those defaults. This is not the newly specified email geometry of 46/24/12. The email raster follows the owner's explicit numeric correction; this email-only task does not edit the web component.

**Removed top-bar provenance (from actual code/history):** The original email gallery `attached_assets/emaili-gostitelju_1787517965745.html` defines `.em .bar{height:5px;background:#157347}` and uses `<div class="bar">`. The initial shared renderer checked in at `3ceb881` instead introduced `COLOUR_BAND`, seven 5px table cells ranging from `#E3BE12` through orange `#E8801B` and other colors; this remained in `LEGACY_THEME`. The welcome-specific version checked in at `03f1e4a` replaced that row with a 3px `#DD9A2B` strip. The reference gallery uses `#DD9A2B` as `--warm` in its `.warn` alert styling (`border-left-color`), not as a license for decorative orange headers. The latest owner correction removes **both** theme band rows altogether, without repurposing warning semantics or changing CTA colors. `renderReadyNotice` no longer depends on matching/removing a welcome strip.
